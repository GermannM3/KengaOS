# Дебаг-заметки: PIO-IDE диск (состояние на 2026-09-01)

## Доказано и работает
- Запись LBA 0/5 и запись selftest — **реально доходят до диска**
  (хост видит паттерны в образе: sector5 = `40 41 42..`, sector100 = wbuf `03 0a 11..`)
- IDENTIFY, ожидания, ERR-проверки, FLUSH убран (ронял следующую команду)
- wait_bsy ПЕРЕД записью регистров — обязательно; DRDY-вариант добавлен

## Открытая проблема
- **Периодичность**: из 6 команд после первого WRITE работает каждая 3-я
  (✓✗✗✓✗✗). READ после первого WRITE возвращает нули (пустой порт),
  часть WRITE молча теряется (без ERR).
- Гипотезы на проверку (в порядке):
  1. QEMU-иде: после WRITE PIO нужен повторный select устройства +
     чтение ALTstatus перед следующей командой (см. hw/ide/core.c:
     ide_transfer_stop / s->status).
  2. IRQ14 (вектор 0x2E) приходит и портится состояние — замаскировать
     IRQ14 в PIC (outb(0xA1, 0xFF)) при поллинг-драйвере.
  3. 400нс-задержка (outb 0x80) после выбора устройства и после команды.
  4. Сравнить с минимальным рабочим примером: osdev "ATA PIO Mode" —
     там после каждого сектора читается ALT status.

## Где смотреть
- `kernel/drivers/pioide.c` — драйвер (аккуратный, канонический порядок)
- `kernel/kmain.c:~495` — selftest w/r + LBA 0/5/100 диагностика
- `kernel/fs/fat32.c` — FAT32 (готов, ждёт диск)
- Хост-проверка: `mformat -F -i test.img`, потом `mdir -i test.img ::/`
