# Телефонный трек — цель, статус, путь до fastboot boot

Обновлено: 2026-09-05. Этот документ — канонический статус по телефонам.
План bring-up ядра (общий для любой SoC) — в `docs/PORT-ARM64.md`.

## Кандидаты

| Телефон | SoC | Статус | Решение |
|---|---|---|---|
| **POCO M4 Pro** | **MediaTek**: 4G = Helio G96 (MT6781), 5G = Dimensity 810 (MT6833) — вариант уточняется | подключен по USB, режим разработчика включён | **основной трек** |
| Oppo A5 2020 (CPH1931RU) | Qualcomm SM6125 | загрузчик закрыт: переключатель OEM-unlock скрыт, Deep Testing заявка подана (вероятность низкая — RU-прошивка) | пауза; вернуть при одобрении Oppo |
| Samsung S21 | Exynos 2100 / SD888 | в резерве (Knox усложняет разблокировку) | после POCO |

## Почему POCO — хорошая новость

Обе версии M4 Pro — **MediaTek**. Для MTK существует **mtkclient** —
открытая bootrom-эксплойт-разблокировка, работающая **без разрешения
вендора и без ожидания** (в отличие от Oppo/Xiaomi-заявок). Это реальный
путь до `fastboot boot kengaos-phone.img`. Ограничение: работает не на
всех revision bootrom (устройства ~2023+ частично закрыты) — совместимость
проверяется при первом доступе к BROM.

⚠️ Разблокировка **стирает данные** телефона. Перед ней — всё сохранить.

## Текущее состояние подключения (2026-09-05)

- Windows видит телефон: `USB\VID_2717&PID_FF40 "POCO M4 Pro"`
  (серийник HQNNBY5HWOCYYPNN), VID 2717 = Xiaomi.
- `adb devices` пуст: ADB-интерфейс есть, но **нет драйвера** (драйвер
  Google r13 знает только VID_18D1; ставить неподписанные Xiaomi-драйверы
  не стали).
- **Рабочий путь — беспроводная отладка** (Android 11+, драйверы не нужны):
  1. Телефон и ПК в одной Wi-Fi сети.
  2. Для разработчиков → «Отладка по USB (беспроводная)» → включить.
  3. «Сопряжение устройства с кодом» → IP:порт и 6-значный код.
  4. С ПК: `adb pair IP:PORT КОД` → `adb connect IP:PORT`.
- После `adb shell` станет известно: точная модель (4G/5G), SoC, версия
  MIUI/Android, состояние загрузчика (`fastboot getvar unlocked`),
  список разделов → выбор версии mtkclient-сценария.

## Путь до первого `fastboot boot` (порядок)

1. `adb pair` + `adb connect` — полная видимость телефона с ПК.
2. mtkclient: BROM → разблокировка загрузчика (стирает данные!).
3. Образ: ядро aarch64 (gzip, raw arm64 Image-обёртка) + DTB →
   `kengaos-phone.img` (`scripts/mkbootimg.py` готов, round-trip тест есть).
4. `fastboot boot kengaos-phone.img` — RAM-загрузка **без сноса**:
   перезагрузка = снова Android, ноль риска.
   Примечание: при `fastboot boot` RAM уже инициализирована загрузчиком
   телефона, DTB устройства передаётся ядру — DRAM-init не нужен.
5. Bring-up по чек-листу (`docs/PORT-ARM64.md`, этап 3): фреймбуфер →
   тач → Wi-Fi → BT → модем.
6. Только после зелёного чек-листа — `fastboot flash` (снос Android =
   установка KengaOS).

## Что уже готово на стороне ядра

- aarch64-ядро: грузится, Aurora-десктоп, FDT-парсер (память/UART),
  GICv2 + groundwork GICv3, ring 3, магазин, пророк — SMOKE OK в QEMU (CI).
- `scripts/mkbootimg.py` — packer Android boot image v0.
- MTK-специфика ещё **не** начата: GIC-версию и адреса устройств берём
  из DTB телефона (уточнить после adb).

## Не хватает (по порядку)

1. Доступ adb (ждёт IP:порт+код от владельца).
2. Raw arm64 Image-обёртка ядра (сейчас ELF для Limine; телефону нужен
   Image-формат: голова `arm64`, x0 = DTB).
3. GICv3 отладка в QEMU (`-machine gic-version=3`) — groundwork уже в
   `kernel/aarch64/intr_a64.c`.
4. Фреймбуфер от загрузчика (simple-framebuffer node в DTB).
