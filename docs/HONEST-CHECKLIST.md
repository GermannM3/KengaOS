# Честный чек-лист KengaOS — что увидят компании и пользователи

Дата: 2026-09-05 · Версия: v0.7.2 + UI-оболочки · Проверено по коду:
`kenga-lang/` (v3.13), `kernel/`, `src/` (десктоп + мобилка).

## Видение

ОС нового поколения: системный слой написан на языке Kenga (UI — тоже
постепенно), и система «ткёт» пророков в себя — агенты с памятью и
предсказанием (Prophet) работают как часть ОС, а не как приложение.

---

## ✅ ЧТО РЕАЛЬНО ЕСТЬ СЕГОДНЯ (проверено, не маркетинг)

### Видит пользователь (ISO на ноутбуке / в QEMU)
- Живой рабочий стол **Aurora**: окна с перекрытием, dock, topbar,
  обои с дрейфующим свечением. Логика десктопа — **на Kenga**
  (`desktop.kenga`, 793 строки, `ui.kenga`, `kmain.kenga`), компилируется
  `emit-c --freestanding` и грузится на голое железо.
- **Терминал** с командами, **чат с агентом** (печатает текст — агент
  отвечает через IPC).
- **4 системных агента** как процессы ОС: logger / agent / model /
  researcher — с IPC, правами (capabilities) и очередями. Видны в
  «AGENT SPACE».
- **Модель-агент ONLINE**: настоящий MLP 2-2-1 в ядре, обучен на XOR,
  инференс через IPC с проверкой прав (`CAP_MODEL_INFER`).
- **Магазин**: 5 пакетов `.kpkg`, установка из input-бара, тест в CI.
- **Prophet как системный сервис** (v1): `kernel/kf_prophet.c` — память
  эпизодов + ядро паттернов, surprise (RMSE), k-NN foresee; тикает из
  десктопа (`kd_prophet_tick`), прогноз виден в SYSTEM HEALTH.
- **Ring 3**: ядро при загрузке запускает пользовательскую ELF-программу
  (user-страницы, GDT/TSS, `int 0x80` write/exit) — фундамент приложений.
- **xHCI USB**: работает в QEMU на обеих архитектурах (тач-планшет,
  ECAM-скан, слоты, CONFIG_EP); на живом железе не проверен.
- **Две архитектуры одним исходником**: x86_64 ISO + aarch64 (QEMU, CI).
- **Каждый коммит** автотестируется: ядро реально грузится в QEMU на
  обеих архитектурах, включая установку пакета и ring-3 запуск.

### UI-оболочки (прототипы на веб-стеке, общий kernel bridge)

Честно: это React/Vite-прототипы поверх симуляции kernel bridge —
контракт тот же, что у ядра (37 `kd_*`); порт в Kenga/C — по `docs/design/design.md`.

- **Десктоп**: окна с перекрытием, dock, лаунчер, topbar, терминал,
  **браузер** (внутренние страницы `kenga://` + внешние сайты), **три
  темы** (Полярная / Синяя волна / Зелёная волна — переключатель в topbar).
- **Мобилка**: boot → lock (свайп) → home (виджет, сетка, док) → шторка
  быстрых настроек → лаунчер; **экранная ЙЦУКЕН-клавиатура**; **браузер**
  (реальная навигация, назад/обновить, умный ввод адреса); **звонилка**
  (цифры, `*0#`, журнал, экран вызова); темы — те же три, в шторке.
- Браузер честно: рендерит движком хоста (iframe) — оболочка пока живёт
  внутри браузера; в будущей ОС это свой движок / порт (Servo-класс).

### Видит разработчик / компания
- **Язык Kenga v3.13** — полноценный: i64/f64/bool/str/list/**Tensor**/
  **Memory**/structs, if/while/for, imports, события (`on "tick"`),
  FFI-интринсики. Компилятор: `kenga run / emit-c / build`, плюс
  **kenga-lite** (C99-хост без Rust) и bytecode-рантайм. VS Code
  расширение, книга, примеры.
- **Prophet/Memory API в языке** (это и есть «пророки»):
  `memory() / learn / predict / foresee / surprise / remember / recall /
  consolidate / save_mind / load_mind` — локальный инференс с памятью
  паттернов, консолидацией во сне (EWC-lite), сохранением разумов
  (`.km`-файлы, совместимы с Rust-хостом).
- **Тензоры + мультимодальность**: `t_matmul / t_sgd_step / load_ppm /
  load_wav` — входы изображений и звука.
- **Единая поверхность ядра** для desktop и mobile:
  37 `kd_*`-функций (агенты, IPC, память, мышь/тач, uptime) — тот же
  контракт, что декларирует `kernel_bridge.kenga`.

## ⚠️ ЧЕГО ПОКА НЕТ (честно)

| Область | Реальность | Что нужно |
|---|---|---|
| **Kenga-программы пользователей** | Ring 3 работает, но в store лежат манифесты, а не Kenga-приложения | Kenga→ELF user-runtime (emit-c уже умеет freestanding C → gcc → ELF = .kpkg с бинарём) |
| **Многозадачность user-mode** | Ring 3 v1 = один foreground-процесс; на aarch64 тредов нет (агенты cooperative) | aarch64 context switch, вытесняющий планировщик |
| **USB мышь/клавиатура на реальном железе** | xHCI работает в QEMU (обе арх); на ноутбуке не проверен | Тест на живом ноутбуке |
| **Диск: запись** | ATA PIO только чтение; NVMe/AHCI нет | AHCI/NVMe + файловая система с записью |
| **Wi-Fi / BT / звук / батарея / ACPI** | Ничего | По порядку: ACPI → Wi-Fi → звук |
| **Телефон** | Основной кандидат — **POCO M4 Pro (MediaTek)**: подключен, режим разработчика включён, adb ждёт беспроводного сопряжения; Oppo A5 2020 — пауза (загрузчик закрыт) | Путь и порядок — `docs/PHONE-TRACK.md` |
| **Браузер как движок** | Оболочечный браузер рендерит движком хоста (iframe); своих рендереров нет | Сетевой стек в ядре → HTML-подмножество своим UI → порт движка в userspace (масштаб: годы) |
| **UI на Kenga** | Логика десктопа в ядре — на Kenga; веб-оболочки — прототипы; рендер-примитивы ядра — C (`kf_fb/kf_design`) | Осознанно: примитивы в C, логика в Kenga (`docs/design/design.md`) |

## 🎯 РАЗРЫВ МЕЖДУ ВИДЕНИЕМ И РЕАЛЬНОСТЬЮ — 3 ключевых шага

1. ~~**«Пророки в системе»**: порт Prophet-Lite в ядро~~ — **сделано**:
   `kf_prophet.c` (v1) тикает из десктопа, прогноз и surprise видны в UI.
   Дальше: глубже память (`.km`-файлы в ядре), предсказание на системных
   событиях (IPC/файлы), не только мышь.
2. **Kenga-приложения в магазине**: `.kpkg` v2 = Kenga-исходник →
   `emit-c --freestanding` → gcc → ELF в ring 3. Цикл сборки уже есть,
   не хватает packaging-конвейера и syscall-обвязки для Kenga-рантайма.
3. **Ежедневная пригодность ноутбука**: xHCI на живом железе →
   AHCI/NVMe (чтение+запись) → ACPI → Wi-Fi.
4. **Телефон**: adb (беспроводное сопряжение) → mtkclient →
   `fastboot boot` из RAM → чек-лист железа (`docs/PHONE-TRACK.md`).

## Итоговая формулировка (можно давать компаниям)

> KengaOS — ОС, системная логика которой написана на языке Kenga —
> языке для живого ИИ (память, предсказание, агенты). Сегодня: рабочий
> стеклянный десктоп на голом железе x86_64 и ARM64, агенты с IPC и
> правами, инференс в ядре, магазин пакетов, ring-3 приложения,
> автотесты на каждый коммит. Завтра: агенты-пророки Prophet как
> системный сервис — ОС, которая помнит и предсказывает.
