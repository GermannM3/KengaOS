# Research Philosophy

Две независимые экспериментальные ветки исследования малого AI. Обе доведены
до стадии реального опубликованного артефакта: результаты запускаемы, а не
теоретичны.

## Ветки

- Kenga — KengaOS + Kenga Prophet. Transformer, ~11K параметров,
  предсказание токена 75.9%, 0/9 выполнение Kenga-кода. Проблема:
  представление данных.
- Z — Z-System-ZBorn. RNN, 4.46M параметров, perplexity 53.2 на смешанном
  корпусе, связный текст. Модель рождена в факторизованном пространстве.
  Проблема: представление параметров.

## Ключевой тезис Z-Born

Главное утверждение проекта Z: модель обучалась непосредственно в
факторизованном пространстве U·S·V^T, а не сначала как обычная плотная сеть,
после чего была сжата через SVD.

```
обычная сеть                 Z-Born
    |                           |
обучение                    U, S, V
    |                           |
SVD                             |
    |                     обучение (рождение в низкоранговом
truncate                   пространстве с самого начала)
```

Это не эксперимент «можно ли сжать маленькую модель». Это эксперимент:
можно ли построить обучение так, чтобы низкоранговая структура была
естественным пространством параметров с самого начала.

## Статус утверждения «collapse-immune»

Пока доказано: Z-Born рождена в факторизованном представлении и не требует
post-hoc truncation. Утверждение «collapse-immune» требует отдельного
фальсифицируемого эксперимента.

### Протокол рангового теста

- Z-Born: rank 32 baseline, затем rank 24 / 16 / 8 / 4.
- Контроль: плотная RNN того же размера, затем SVD-truncate до тех же рангов.
- Итог — кривая quality(rank) для двух веток.

Ключевое следствие: сравнивать по eval-метрике при одинаковом числе
eval-параметров. При обучении dense тратит больше compute — фиксировать
отдельной колонкой, не смешивать.

### Метрики коллапса (спектральные)

- Participation ratio PR = (sum(sigma_i))^2 / sum(sigma_i^2) — мера
  заполненности ранга. Collapse = PR стягивается к 1.
- Condition number sigma_max / sigma_min во время обучения — если sigma_min
  уходит в 0, сеть сама выбрасывает ранг.

Ожидание: Z-Born показывает стабильный PR примерно равный целевому рангу и
ограниченное condition number на всём обучении; dense-then-truncate — резкое
падение качества после усечения.

### Спектральная преемственность (бонус)

Ранговый рост: можно ли модель ранга 8 дорастить до ранга 16 дообучением,
когда новые сингулярные значения стартуют с нуля. У плотной сети такого
понятия нет. Если сработает — чистый результат в пользу born-in-Z.

## Z-BIG 203M — масштабный контроль

Loss сам по себе ничего не доказывает. Вопрос Z-BIG: сохраняется ли эффект
при масштабировании. Зафиксированные метрики:

1. Validation NLL
2. Perplexity
3. Качество генерации
4. VRAM
5. tokens/sec
6. Число параметров
7. Effective rank
8. Spectral distribution

Сильный вариант: A/B Dense 203M против Z-factorized 203M.

## Разделение задач

- Kenga: модель получает память, инструменты, вычисления и взаимодействие
  с окружающей системой — model + memory + tools + runtime + decoder + OS.
  Проблема — представление ДАННЫХ.
- Z: как устроена внутренняя физика параметров — U, S, V, rank, collapse,
  recovery, spectral state. Проблема — представление ПАРАМЕТРОВ.

Путь развития:
- Kenga: representation -> architecture -> compiler/runtime ->
  constrained generation -> memory.
- Z: factorization -> rank -> collapse -> spectral dynamics -> recovery.

## Порядок работы

Не объединять идеи, потому что они «кажутся совместимыми». Сначала каждая
система самостоятельно достигает работающей модели, затем ставится вопрос:
даёт ли объединение дополнительный эффект.

- Kenga Prophet: первый работающий генератор Kenga-кода.
- Z-Born: ранговый тест (протокол выше).
- Z-BIG: масштабный контроль с зафиксированными метриками.

Потенциальное объединение — третий отдельный эксперимент:
DATA -> Kenga representation -> Z representation -> tiny neural model ->
Kenga runtime -> working AI agent.
