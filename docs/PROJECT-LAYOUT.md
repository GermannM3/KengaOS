# Раскладка проекта и правило параллельной работы

## Одна философия
KengaOS = одно ядро (десктоп + мобилки). Сборки не различаются ядром:

| Цель | Скрипт | Артефакт | Где живет |
|---|---|---|---|
| x86_64 ISO (десктоп/ноут) | `scripts/build.sh` | `build/kengaos.iso` (+kernel) | `boot:` с Limine |
| aarch64 (мобилка/QEMU virt) | `scripts/build-a64.sh` | `build/a64/kernel-a64.elf` → `build/a64/kengaos-a64.img` (UEFI+Limine) | `run-a64.sh [--headless]` |

## Где что лежит (кто что может менять)

| Путь | Содержимое | Владелец (работает параллельно) |
|---|---|---|
| `kernel/` | **единое ядро**: `kmain.kenga` (оркестратор), `kf_*.c` (C-нативы: диск, USB/xHCI, пророк `kf_prophet.c`, магазин `kf_pkg.c`, ring 3 `kf_user.c`), `aarch64/` (арх-слой), `crt/` (шим-заголовки) | общее, но перемещаются только отдельные `kf_*` |
| `kernel/kf_disk.c` | **PIO-IDE диск** (порт из legacy C-ядра; IDENTIFY, LBA28/48 R/W) | я (диск/драйверы) |
| `kernel/kf_usb*.c` | xHCI (обе арх) + UHCI-фолбэк + HID (таблет-мышь) | второй агент |
| `kenga-desktop/` | нативный десктоп на Kenga (`.kg`-исходники) | второй агент |
| `kenga-lang/` | сабмодуль компилятора (пушится отдельно) | общий (сабмодуль, не форсить) |
| `src/` + `mobile.html` | **оболочки (прототипы, общий kernel bridge)**: десктоп (окна/док/лаунчер/браузер/темы) и мобилка v2 (экранная клавиатура, браузер, звонилка, темы); `src/theme.js` — темы, `src/components/BrowserApp.jsx` — общий браузер | второй агент |
| `scripts/` | сборщики обоих образов + a64-sed-слой | общее, менять через PR-код-ревью |
| `docs/` | дизайн, roadmap, research | общее |
| `legacy/` | старые прототипы и альтернативные C-ядра | **архив, вне git** (игнорится) |

## Правила параллельной работы (чтобы не конфликтовать)

1. **Кто что написал — тот и правит в своём домене**: второй агент: `src/mobile/*`, `mobile.html`, `kenga-desktop/*`, `kernel/kf_usb.c`. Я: `kernel/kf_disk.c`, дисковые/сетевые драйверы, `docs/`, диск-зависимые части `scripts/`.
2. **Не трогаем чужие незакоммиченные файлы** — они остались в рабочем дереве `main` (видно по `git status`).
3. **CI показывает состояние обоих образов**: `os-smoke` (x86 ISO + QEMU) и `os-smoke-aarch64` (aarch64 ELF + QEMU virt) — обе зелёные = база стабильна. Красная = ветка/ревизия общая — сначала смотрите в workflow-лог, потом договаривайтесь, кто регресс.
4. **Ветки**: основная работа — `main` (после ревью). Мой драйверный блок уже в main (см. `kernel/kf_disk.c`, вызов `disk_init()` в `kmain.kenga`).
5. **Сабмодуль `kenga-lang`**: пин (v2.0.0-169) — менять только если компилятор реально обновился и обе сборки прошли.

## Проверка после изменения
```bash
# десктоп
PKG=...; bash scripts/build.sh          # ISO + smoke
# мобилка
bash scripts/build-a64.sh && bash scripts/run-a64.sh --headless
```
