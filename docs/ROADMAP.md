# Дорожная карта KengaOS

Калиброванный план от текущего состояния (v0.0.1) до KengaOS v1.0.

Каждый milestone — критерий готовности, а не срок. Сроки оценочные.

---

## v0.0.x — Бутстрап на C

**Цель:** доказать, что KengaOS грузится и работает.

| Версия | Что добавляется                              | Статус |
|--------|----------------------------------------------|--------|
| 0.0.1  | Limine + UART + framebuffer + GDT/IDT/PIT    | ✅     |
| 0.0.2  | Buddy page allocator                         | ✅     |
| 0.0.3  | Round-robin планировщик + потоки             | ✅     |
| 0.0.4  | VFS (initrd), RU-раскладка, spinlock/semaphore | ✅     |
| 0.0.5  | User mode (ring 3), VMM, syscall, ELF loader | ✅     |
| 0.0.6  | FAT32 read/write на реальном диске           | ⬜     |
| 0.0.7  | Network stack (lwIP)                         | ⬜     |
| 0.0.8  | Multi-core (SMP)                             | ⬜     |

**Критерий выхода из v0.0:** ядро, которое грузится, печатает русский текст,
читает файл с диска, и держит несколько «процессов» (пока потоков).

**Текущее состояние (v0.0.3):**
- ✅ Buddy allocator управляет физической памятью из Limine memmap
- ✅ Round-robin планировщик переключает потоки каждые 10 мс по таймеру
- ✅ Демо-потоки создаются через `spawn` и работают параллельно
- ✅ Команды shell: `threads` (список), `mem` (статистика), `spawn` (демо)
- ⬜ Файловая система
- ⬜ Real user-mode (ring 3)
- ⬜ Sync примитивы (mutex/semaphore)

## v0.1.x — Kenga в user-space

**Цель:** первый Kenga-код работает поверх ядра.

Требует доработки `lower_c` в kenga-lang:
- `--freestanding` режим (без CRT)
- `mmio_read<T>(addr)` / `mmio_write<T>(addr, val)`
- `asm!(arch, code)`

| Версия | Что добавляется                              | Статус |
|--------|----------------------------------------------|--------|
| 0.1.0  | lower_c --freestanding работает в user-space | ⬜     |
| 0.1.1  | libc.kenga (kstrlen/kstrcmp/kprintf)         | ⬜     |
| 0.1.2  | i18n.kenga (миграция i18n.c)                 | ⬜     |
| 0.1.3  | shell.kenga (миграция shell из kmain.c)      | ⬜     |
| 0.1.4  | Запуск .kenga-программ как процессов         | ⬜     |

**Критерий выхода из v0.1:** можно написать `hello.kenga`, скомпилировать
его в freestanding C, и запустить как процесс в KengaOS.

## Что НЕ в роадмапе

Эти вещи мы **сознательно не делаем** до v1.0:

- ❌ **Свой загрузчик.** Limine работает, оставим его.
- ❌ **Свой компилятор C.** GCC/Clang существуют.
- ❌ **Поддержка ARM/RISC-V до v0.4.** Сначала x86_64, потом порт.
- ❌ **Real-time режим.** KengaOS — general-purpose, не RTOS.
- ❌ **Кластерные/распределённые функции.** Один узел, один сеанс.
- ❌ **Поддержка legacy BIOS.** Только UEFI (Limine умеет и BIOS, но
  мы целимся в современное железо).

## Приоритеты

Если приходится выбирать, что делать первым:

1. **Доказать, что что-то работает** (v0.0.x → v0.1.x).
2. **Мигрировать на Kenga** (v0.1.x → v0.3.x).
3. **Использовать Kenga-нативные фичи** (v0.4.x).
4. **Делать оболочки** (v0.5.x → v0.6.x).

Делать оболочки до ядра — собирать карточный домик. Делать ядро
без Kenga-миграции — написать ещё один unix-like.
